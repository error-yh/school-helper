# S8-WIDGET-01 技术报告

## 实现

桌面显示设备日期、星期和学期范围内的教学周。当前尚未结束的有效安排按实际开始时间稳定排序，显示前两门。卡片显示名称、地点和开始／结束时间，空间足够时显示教师并增加留白。开课前 10 分钟显示「即将开始」，开课后至结束前显示「进行中」。课程结束时重新选择前两门。当天无课或全部结束时，显示明天最早一门有明确时间的安排。未定位的安排不会填入猜测时间。没有可显示课程且仍有未定位安排时，显示「部分课程缺少有效时间」。

小组件使用 Android AppWidgetProvider 与 RemoteViews。4×2/4×3 根据 Launcher 报告的 dp 适配。标题打开今天，明日预览打开对应日期，课程详情按 Profile、课程 ID、安排 ID、例外 ID 和有效日期重新解析。课程删除、移出日期或切换 Profile 后，旧链接回到今日课表。

## 数据和时间

以 v0.2.1 的 Room Schema 5 和活动 Profile 为唯一来源。Widget 复用 TimetableRules.occurrencesOn() 和 teachingWeek()，通过只读事务快照读取已提交的设置、课程、节次与单次例外。Widget 读取不会补写学期或作息。导入、作息修改、调课、停课、补课、撤销和 Profile 激活／恢复走原有的修订观察流。

将有效安排在设备时区转换为实际时间区间。多节连堂取首个实际开始、最后一个实际结束。调课或补课覆盖优先由领域规则解析。可见课程的即将开始、开始、结束，以及次日零点，取严格在当前时间之后的最早节点。所有 Widget 实例共享一个可替换的 AlarmManager 非精确 RTC_WAKEUP 闹钟。最后一个实例移除后取消闹钟。广播执行时重新读取最新快照，延迟到达时会一次跳过所有已结束课程。打开 App、数据提交、重新配置、系统时间和时区变动、重启或更新后也会触发重算。暂时无法查询时显示错误状态，并保留次日重试及上述事件恢复入口。

使用 setAndAllowWhileIdle，系统仍可推迟派发。Doze、省电及厂商后台管控的条件会影响实际延迟。调试包记录计划时间、Alarm 实际回调和发布的时间戳。平台约束见 [Android 闹钟调度](https://developer.android.com/develop/background-work/services/alarms)。

## 安装与验收步骤

1. 安装隔离 APK，打开测试版一次。包名为 io.github.schoolhelper.app.widgettest，可与正式包共存。
2. 在测试版内创建或导入用于验收的课表。建议准备三门时间有间隔的课程和一门明日课程。
3. 在桌面长按空白处或双指捏合，打开「小部件」，选择校园助手的「今日课程」并添加。HyperOS 可从「小部件 → 全部应用 → 安卓小部件」查找，选择校园助手应用下的项目。长按小组件后拖动边框可调整大小。
4. 分别点击标题、两门课程和明日预览，核对日期与对应安排。记录课程结束配置、计划触发、实际回调、桌面更新和当时的电源／屏幕状态。
5. 可单独从桌面移除小组件或卸载 .widgettest 测试包。

## 构建与自动化验证

- 应用与 instrumentation APK 已离线构建。首次构建受旧 Gradle 缓存权限影响。使用独立进程、干净构建输出、可用的本地依赖和专用调试签名目录恢复。
- WidgetScheduleTest 6 项、CalendarOccurrenceTest 11 项、TimetableRulesTest 28 项，合计 45 项通过。不同作息样本 08:00–09:40、08:30–10:05、09:00–10:30、13:30–15:10 均验证开课前 10 分钟、开课、下课和重新选课的边界。其余用例覆盖重叠和同名课程、连堂、日期跨越、调课、停课、补课、修改作息与旧链接失效。
- Android Lint 0 错误、69 警告。小组件相关警告为 Android 12 起采用的格数提示，以及紧凑状态标签字号。旧 Android 使用 dp 最小尺寸。
- Redmi K70（vermeer，Android API 36）通过 1 项平台 RemoteViews 渲染测试，验证了 104dp／166dp 布局、长名、地点与教师、时间、深浅色文字和明日预览。该测试使用 Android 原生渲染，独立于 Launcher。
- USB 安装首次被系统拒绝，用户确认后成功安装两个隔离测试包。Launcher 快捷固定测试首次因后台启动受限失败，测试夹具改用仓库已有的前台启动方式。实际 Launcher 验收使用用户在最后一页添加的正确实例。
